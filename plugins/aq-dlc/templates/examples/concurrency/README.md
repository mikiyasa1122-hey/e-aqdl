# 並行処理・共有リソースのテスト例（E-AQDL）

リスクに並行処理の種類（`risk ... --concurrency`）を付けたときに、検証で求める「処理順序を制御したテスト」の例です。
Python の標準ライブラリだけで書いています。考え方は他の言語でも同じです。

- **順序は、固定時間の sleep ではなく、差し込み口（hook）・バリア・イベントで決める。** sleep に頼ると、遅い環境で順序が入れ替わって、たまたま通る・たまたま落ちるテストになる。
- **待つときは必ず期限を付け、失敗しても待機とロックを解放する**（`Event.wait(timeout)`・`Barrier(timeout=…)`・`try/finally`）。テストが固まらないように。
- **期待する失敗・ロールバック・最終状態を、すべて確かめる**（例外の種類だけでなく、DB に何が残ったか）。
- **直し方は、問題に合った最小のものを選ぶ。** 一律にロックを足さない。楽観的排他（version）、条件付き更新、ユニーク制約、冪等キー、トランザクションで足りることが多い。

| ファイル | 例 |
| --- | --- |
| `inventory.py` | 例の対象（SQLite の在庫と予約）。各操作に差し込み口 `hooks.before_write(step)` がある |
| `test_concurrency_examples.py` | TOCTOU（確認の後の削除）・lost update（楽観的排他）・二重登録（冪等キー）・途中の失敗（ロールバック）・別スレッドからの同時更新（バリア） |

実行: `python3 -m unittest test_concurrency_examples -v`（このフォルダで）
