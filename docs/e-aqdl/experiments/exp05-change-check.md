# 仕様変更が意図どおりかの判定表（実験05）

対象を起動し、実際にリクエストを送って判定する（コードと README は使い方を知るため、および C7 のためだけに読む）。
利用者はメンバー2人（alice・bob）と管理者1人を用意する。

各項目: 満たす / 一部満たす / 満たさない / 確かめられなかった（理由）。満たさない・一部には、リクエストと応答を書く。

| # | 意図 | 確かめ方 |
|---|---|---|
| C1 | 管理者が他人のメモ（公開・非公開とも）の内容を編集できる | 管理者で alice の公開メモ・非公開メモのタイトルや本文を更新 |
| C2 | 管理者が編集したら、最後に編集した人と日時がメモの取得で分かる | C1 の後に取得し、編集者（管理者）と日時が返るか |
| C3 | タイトル51文字は作成・更新とも拒否、50文字は通る | 作成と更新の両方 |
| C4 | すでに保存されている51文字以上のタイトルのメモが、取得で元のまま返り、本文だけの更新ができる | サーバーを止めて DB に直接 80文字タイトルのメモを入れる（SQLite なら sqlite3 モジュールで INSERT。列は既存の行を参考に）→ 起動して取得・本文だけ更新 |
| C5 | 回帰: メンバーは他人のメモを編集できないまま | bob が alice のメモを更新 → 拒否 |
| C6 | 回帰: 非公開は他メンバーに見えない・削除済みを管理者が復元できる・検索できる・自己登録できない | それぞれ1回ずつ確認 |
| C7 | 古い記述が残っていない | README とテストに「管理者は他人のメモを編集できない」「タイトル100文字」の記述が残っていないか。成果物自身のテスト（pytest）がすべて通るか |

最後に合計（7点満点、一部=0.5）。
