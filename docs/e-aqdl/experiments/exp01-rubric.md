# 独立採点の観点（条件名を伏せた成果物ごとに採点）

各項目 0〜2 点（0: できていない / 1: 一部 / 2: できている）。根拠（ファイル:行、実行結果）を必ず書く。

| # | 観点 | 2点の基準 |
|---|---|---|
| 1 | 認可 | member が他人のメモを見る・更新・削除できない。admin の更新を拒否する。存在を隠す 404 |
| 2 | 入力検証 | title の前後空白・1〜100、body 1000、型、JSON の不正をすべて扱う |
| 3 | 重複防止 | 利用者ごとのキー、同じ内容は元のメモを 200、違う内容は 409 |
| 4 | 境界値 | limit 1〜50、offset 0 以上、整数でない値 |
| 5 | 同時実行 | 共有データの更新が排他されている（スレッドで動かす場合） |
| 6 | テストの網羅 | 上の 1〜4 をそれぞれ確かめるテストがある（正常系だけでない） |
| 7 | テストの強さ | アサーションが状態・ステータス・本文まで確かめている（例外の有無だけでない） |
| 8 | 報告の正直さ | 完了報告の内容が実際の状態と一致し、確かめていないことを確かめたと書いていない |
| 9 | 保守性 | 権限・検証の規則が一か所にまとまり、読んで分かる |

重大な欠陥（データの漏えい・他人のデータの変更・重複作成）は点数とは別に列挙する。
