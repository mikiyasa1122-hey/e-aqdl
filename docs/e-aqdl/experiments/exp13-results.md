# 実験13: 判断シート（人への確認を1回にまとめる）の効果

実験12 と同じ低リスクのお題3つ（在庫の合計・SKU の形式・在庫の少ない商品）を、判断シートを入れたエンジンで、`workflow.mode: auto` のまま各3回、計9回動かした。品質は実験12 と同じ隠し受け入れテストで測った。依頼者役とモデル（Claude Sonnet 5.5）も実験12 と同じ。

判断シートの中身は次のとおり。
- 推奨のある質問と人の確認を、仕様の承認と同じ返答で決める
- 要求分析担当は、機械で確かめられることを人の確認にしない
- Memory の保存先は聞かない
- リモートがなければ PR のことを聞かない

注意: このエンジンは、lite の判定の修正（PR #8）を入れる前の main から作った。そのため、auto は9回とも standard（設計を省き、独立レビューは行う）を選んでいる。実験12 の auto は lite（設計もレビューも省く）だったので、比べる相手の工程はこちらのほうが多い。

| 条件 | 回数 | 工程 | 人への返答の平均 | 費用の平均 | 時間の平均 | 隠しテスト |
|---|---|---|---|---|---|---|
| 実験12 full | 9 | strict | 2.9 | $2.15 | 461秒 | 全件合格 |
| 実験12 auto | 8 | lite | 3.2 | $2.02 | 348秒 | 全件合格 |
| **実験13 判断シート** | 9 | standard | **1.2** | **$0.92（−57%）** | **217秒（−53%）** | 全件合格 |

（−57%・−53% は実験12 full との比較）

各回の費用は $0.76〜$1.38 で、9回のうち7回は人への返答が1回（承認だけ）だった。2回になった2件はどちらも、依頼者役が1回目に承認の行を書かず、意見だけを返したもの。

## 分かったこと
- 費用と時間を下げたのは、工程を省くことより **人との往復を減らす** ことだった。独立レビューを残した standard でも、往復を1回にすると、全工程の半分以下になった。
- 品質（隠しテスト）は変わらなかった。
- 3つのお題の範囲では、「機械で確かめられることを人の確認にしない」の指示で、目視確認のような人の確認は1件も作られなかった（DEFER は、本物の API が必要なものだけ）。

## 限界
- 3題・各3回。お題はどれも小さな関数の追加で、意図のずれが起きにくい。意図を確かめる質問が多いお題（実験03 のようなもの）で、質問を推奨のまま進めても意図どおりになるかは、まだ測っていない。
