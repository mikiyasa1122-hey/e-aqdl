# 比較実験 01: Claude Code 単体と E-AQDL

## 目的
同じお題・同じ返答で4つの条件を動かし、成果物の品質（隠しテスト・落とし穴の検出・テストの欠陥検出能力）とコスト（時間・トークン・人間への質問）を比べる。各条件1回のため、結果は「傾向」として扱い、改善の証明とはしない。

## 条件
| # | 条件 | 設定 | 最初のプロンプト |
|---|---|---|---|
| ① | 普通の Claude Code | プラグインなし | task.md の全文 |
| ② | テスト付きの Claude Code | プラグインなし | task.md の全文＋「単体テストを書き、すべて通ることを確認してから完了と報告してください。」 |
| ③ | E-AQDL（Memory なし） | プラグインあり、counterfactual.mode = off | task.md の全文 |
| ④ | E-AQDL（Memory あり） | ③と同じ＋事前の run（warmup.md）で作った Memory | task.md の全文 |

④の事前の run: warmup.md を E-AQDL で最後まで動かし、学びを共有候補として人間（実験者）が承認して共通 Memory に入れる。本番の④は開始時に「共通 Memory も使う」を選ぶ。③は「Memory を使わない」を選ぶ。

## そろえる条件
- モデル・Claude Code の版・`--max-turns`（各ターン 60、続行は最大 10 回）
- 作業フォルダ: 空の git リポジトリ（初期コミットのみ）。条件ごとに別のフォルダ・別の AQDLC_HOME
- 返答: replies.md の決まった返答を、状況に応じて自動で返す（人の判断を入れない）
- 隠しテスト・参照実装は、すべての run が終わるまで、作業フォルダから見えない場所に置く

## 測るもの
| 観点 | 方法 |
|---|---|
| 仕様どおりか | 隠しテスト（31件、6観点）の合格数。観点ごと（基本・認証・認可・入力検証・重複防止・ページング） |
| 落とし穴 | 認可・境界値・重複防止・ページングの観点の合格数 |
| テストの欠陥検出能力 | 成果物の server.py に、同じ Mutation（E-AQDL の mutation.py の Operator）を同じ規則で入れ、各成果物自身のテストが失敗するかを数える（検出率 = killed ÷（killed＋survived）） |
| 完了報告の正直さ | 報告の「確かめたこと」と、隠しテストの実際の結果が食い違っていないか |
| コスト | 経過時間、トークン（入力・出力）、ターン数、人間への質問の回数 |
| 独立した採点 | 実装を見ていない別のエージェントが rubric.md で採点（条件名は伏せる） |

## 手順
1. お題・隠しテスト・採点表を固定する（この版）
2. ④用の事前の run（warmup）
3. ①〜④を同じ順で実行（順序の影響を避けるなら、2回目は逆順）
4. 隠しテスト・Mutation・独立採点を実行
5. 結果を表にまとめる。差が小さい・1回だけの結果は「傾向」と書く
