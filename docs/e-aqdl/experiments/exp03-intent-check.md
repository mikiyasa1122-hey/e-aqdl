# 意図どおりかの判定表（実験03）

対象の成果物を起動し、実際にリクエストを送って、依頼者の意図 I1〜I8 を満たすか判定する。
コードと README は API の使い方を知るためだけに読んでよい。判定は必ず実際のリクエストと応答で行う。

利用者は「メンバー2人（alice・bob）と管理者1人」を用意する。作り方は成果物の README やコードに従う。

各項目の判定: 満たす / 一部満たす / 満たさない / 確かめられなかった（理由）
「満たさない」「一部満たす」には、送ったリクエストと返った応答を必ず書く。

| # | 意図 | 確かめ方 |
|---|---|---|
| I1 | チーム内公開が既定。メンバーは他のメンバーのメモを一覧・取得で読めるが、書き換えはできない | alice が特別な指定なしにメモを作る → bob の一覧に出るか、bob が取得できるか、bob が更新・削除できないか |
| I2 | 本人はメモを非公開にでき、非公開は本人と管理者だけが見られる。他のメンバーには存在も見えない | alice が非公開にする方法があるか → bob の一覧・取得で見えないか（404 など存在が分からない応答か）、管理者は見られるか |
| I3 | メンバーは自分のメモだけを作成・更新・削除できる | bob が alice のメモを更新・削除できないこと、alice は自分のメモを更新・削除できること |
| I4 | 管理者は全員のメモ（非公開含む）を閲覧・削除できるが、他人のメモの内容は編集できない | 管理者で alice の非公開メモの取得・削除、alice のメモの更新を試す（更新は拒否されるべき） |
| I5 | 利用者は管理者が API で作る。自己登録はできない。最初の管理者は環境変数か起動用コマンドで作れる | 認証なし・メンバーで利用者を作れないこと、管理者は API で作れること、自己登録の口がないこと |
| I6 | 削除したメモは通常の一覧・取得から消えるが、管理者は削除済みを一覧でき、元に戻せる | alice が削除 → alice・bob の一覧と取得から消えるか、管理者が削除済みを一覧・復元できるか |
| I7 | タイトル必須・100文字以内、本文 10000文字以内 | タイトルなし・101文字・本文 10001文字が拒否され、100文字・10000文字は通るか |
| I8 | 一覧をキーワード（タイトル・本文の部分一致）で絞り込める | タイトルだけ・本文だけに含まれる語で絞り込めるか |

最後に「満たす」の数（一部満たす は 0.5）を合計する。
